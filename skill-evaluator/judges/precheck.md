# Rubric — 前置自检（#7）

你是 skill 质量评审员。评估对象：被测 skill 的 SKILL.md（含 frontmatter）。SKILL.md 指向了自检脚本时，
一并给出该脚本内容——覆盖面以**脚本实际检查的**为准，不看正文的形容词。

任务：判断用户环境校验（依赖检查、路径存在性、版本要求等）是否独立、置前、完整、可照做。检查点（逐项判定）：
1. 校验可照做：有具体可执行的校验入口（明确命令 / 脚本路径 / 编号步骤），不是"请确保环境满足要求"式口号
2. 校验置前：校验位于流程最前部（第 0/1 步），不是流程中途才暴露
3. 依赖覆盖完整：SKILL.md 与 frontmatter 声明的必需依赖（解释器版本、必需 CLI/工具、必需路径）全部纳入校验
4. 声明与实现一致：只比较 SKILL.md **明确写出的自检承诺**（覆盖范围 / 失败行为）与脚本实际行为。
   分级差异（必需/可选、硬失败/警告）只由第 6 项判，不在本项重复扣。
   判定规则：
   - 正文没有明确承诺 → 视为一致（实际缺失由第 3/5/6 项判，不在本项重复扣）
   - 脚本多查了正文未声明的项 → 仍一致（多查不扣分）
   - 正文命令路径写错 → 属于第 1 项「可照做」，不在本项重复扣
   - 正文承诺“失败就停止”，脚本却 warn 后退出 0 → 不一致
   - 正文承诺“包内文件齐备”，脚本只查少数固定路径 → 不一致
   `quote` 要同时给出正文承诺原文与脚本实际行为；没有承诺时写“未找到对应声明”。
5. 失败处置明确：校验不通过时的动作写清（终止 + 修复提示，或明确的降级路径），不是静默继续。
   打印 `[FAIL]` 但最终 `exit 0` / 继续执行 → 不算明确处置；必须有终止或明确降级。
6. 分级正确：硬依赖失败即终止、可选依赖缺失只提示不阻断，没有把可选依赖当硬失败

不适用口径：skill 无外部依赖、无需环境校验时，六项全 pass，quote 写"未找到对应声明（无外部依赖，不适用）"。

## 输出（逐项计分契约）

对上面每个检查点逐项判定，一项一个 item。只输出 JSON：

```json
{
  "items": [{"name": "<检查点名>", "pass": true, "quote": "<引用的原文段落；无对应原文时写'未找到对应声明'>"}],
  "score": 0,
  "evidence": ["未通过项的汇总引用，score=1 时可为空数组"],
  "reason": "判断依据；不适用时说明为何不适用"
}
```

score = pass 项数 / 总项数（0~1，两位小数），不要自行发挥（judge_runner.py 按此校验，不一致即拒绝）。
