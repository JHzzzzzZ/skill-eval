# 沙箱越界检测与评测集 prompt 的路径约束

worktree 只限定 cwd，不限定写权限。自评期间实测三次越界：一条探针 prompt 带了真实仓库路径，
agent 走出沙箱改了评估器仓库的 `README.md`、改了 `judges/precheck.md`，还在被测包目录里留下
`scratch/run_judges_tdd.py`（含宿主硬编码，把该包自己的自检测试打成红）。三处都得人工发现、人工回滚。

决定：

1. `trace_run.py` 增 `--guard-repo <path>`（可重复）：run 前后各拍一次 `git status --porcelain`，
   新增条目写进 `trace["guard"]["escaped_writes"]` 并打印告警；`--guard-revert` 才回退
   （未跟踪→删、已跟踪改动→`git checkout --`）。默认只报告，避免覆盖并行编辑。
2. `evalset_check.py` 增 `out_of_sandbox` 检查：prompt 里出现绝对路径（`C:\`、`~/`、`/home/`…）
   或 `..` 逃逸即命中，`clean=false`（#1 随之降级）。
3. 流程约定写进 reference.md § 沙箱：评测集 prompt 只能引用沙箱内路径；跑完看 `trace.guard`。

原因：为什么不做强制拦截——worktree 方案下做不到（ADR-0001 的已知边界，改 Docker 才可能）；
为什么默认不回退——回退会把"另一个写入者正在编辑的文件"一起吃掉（本仓 AGENTS.md 记录过
生成期间有并行写入者）；为什么检查放在 evalset_check 而不是 prompt 生成时——那一步没有脚本，
只有文档，机械校验必须挂在确定性脚本上。

## Consequences

- 越界从"事后偶然发现"变成"trace 里有字段 + 告警"，但**仍不阻断**：判官/人要看告警才处理。
- `evalset_check` 多一条可能误伤：prompt 里合法地提到 `/tmp` 之类也会命中——写 prompt 时改用相对路径。
- 改 `trace_run.py`/`evalset_check.py` 即改评估器指纹（ADR-0010）：本次改动之前的报告 `comparable=false`。
