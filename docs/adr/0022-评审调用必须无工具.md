# 评审调用必须无工具

ADR-0020 定了"固定单发 prompt"，但 pi 子进程默认带齐全工具，实测判官并不会只看 prompt：
一次 `precheck` 评审里它发起 6 次 bash——`cd` 进**真实仓库**（不是被测副本）读文件、在 /tmp 造实验
（删文件后重跑自检脚本验证"包内文件齐备"），还在被测包目录里留下过 `run_judges_tdd.py`
（含 `C:/Users/.../pi.cmd` 机器路径），直接把该包自己的自检测试打成红的。

决定：

1. 评审调用一律带 `--no-tools`：判官只能用 prompt 里的材料（rubric + 被测文件 + rubric 声明的附属文件）。
2. 判官不得接触被测副本目录之外的任何东西——需要核对"声明 vs 实现"时，把两边材料都放进 prompt，
   而不是让判官自己去翻。
3. `raw/judge-events/<metric>.events.jsonl` 里若出现 `tool_execution_start`，该次评审作废重跑
   （可从事件流机械判定）。

原因：为什么不是"给它工具但限定 cwd"——实测它 cd 出去；为什么不让它做实验——判官一旦能改变输入，
同一 prompt 就不再可重放，"证据必须引用原文"这条也就失去意义（它引用的可能是自己刚造出来的输出）；
判官的职责是判，不是修。

## Consequences

- 涉及"脚本是否真的覆盖了正文承诺"这类判断，材料必须给全（rubric 要声明输入），否则判官只能猜——
  这是 ADR-0021 第 3 条存在的原因。
- 评审成本下降（无探索步），但单次评审对 prompt 里材料的完备性更敏感。
- 改 `reference.md`/`judges/*.md` 即改评估器指纹（ADR-0010）：本次改动之前的报告 `comparable=false`。
