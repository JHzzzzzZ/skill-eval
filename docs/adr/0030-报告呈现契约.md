# 报告呈现契约：表格优先 + 原始 JSON 折叠 + 闸门可见 + 建议与指标同源

三处结构性缺陷在自评报告里同时暴露：

1. **页面是 JSON 浏览器**：19 条指标只有 #15/#12/#4/#9 有定制表格，其余在 HTML 里是裸 `<pre>` 原始 JSON，
   且短于 400 字符时连折叠都没有。
2. **闸门整体 fail 却不可见**：`static.json` 的 `hardcoded`（可移植性闸门，ADR-0008）`report.py` 从未读取——
   闸门只把 `errors` 填非空、`passed=false`，而 `conclusion()` 只看 19 条指标裁决。硬编码绝对路径能让评估
   整体 fail，页面上一个红字都没有。
3. **建议与问题脱钩**：`reference.md` 声称 report.md "每条指标一节：分数/证据/建议"，但"建议"从未实现；
   优化建议只存在于评估会话的对话里，而问题（指标裁决）在报告里——两者可以互相矛盾而无人发现。

决定：

1. **表格优先**：给 #1/#2/#5/#6/#7/#8/#10/#13/#14 写定制表；再加**通用兜底**（dict/list 递归压平成
   key-value 表）——从此没有指标卡裸奔原始 JSON。
2. **原始 JSON 一律保留，有表就折叠**（不管多短），无表且短才内联。信息量不变：HTML 不得比 md/json 少信息。
3. **闸门可见**：`hardcoded` 非空 → #13 裁决 = fail（ADR-0015 已把闸门归到 #13）；`stale_refs`、
   `scan_excluded_dirs` 作为 #13 卡的信息行（不改裁决）。
4. **建议内联 + 汇总页**：`report.json` 顶层新增 `advice` 数组，每项 `{metric, severity, problem,
   evidence, action}`，由 `build()` 从裁决确定性派生（不经 LLM）；report.html 每个指标卡下方内联该指标建议，
   并新增「优化建议」tab 汇总（按严重度排序、带 `#N` 锚点跳回指标卡）；report.md 加 `## 优化建议` 段。
   问题与建议同源，结构上不可能脱钩。
5. **结果符号统一**：pass=绿 ✓、fail=红 ✗、warn=黄 ⚠、skipped=灰 –；用于卡片徽章、表格结果列，
   并新增 19 行总览表（结果栏一眼扫完）。

原因：为什么建议不由 LLM 生成——建议与裁决同源才谈得上"强对应"，LLM 生成的建议会与指标脱钩（正是本次要修的
问题），且每次渲染花 token、产生抖动。为什么 `advice` 进 `report.json` 而不是只在渲染层算——三份产物
（json/md/html）吃同一个源，md 与 html 不会漂。为什么不新增第 20 条指标承载闸门——ADR-0004 固定 19 条。

## Considered Options

- 建议单独一个 HTML 页面、不内联到指标卡：读的人要在两处对照，"这条建议对应哪个问题"仍靠人脑维护。
- 只做折叠、不加表格：折叠后的原始 JSON 仍需人肉解析，19 条指标里 10 条如此。

## Consequences

- `report.json` 多一个顶层 key（19 条指标的 key 数不变）。
- #13 裁决口径变严：历史报告中带绝对路径的 skill 会从 pass 翻 fail（这是修 bug，不是口径漂移）。
- 通用兜底表对深层嵌套 dict 会压平成长表（如 #12 的 model_robust 子树）——信息不丢，但可读性依赖
  上面的定制表；两者的取舍写进注释，不做自动选择。
