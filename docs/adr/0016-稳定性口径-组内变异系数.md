# #12 稳定性按组内（逐 case）变异系数裁决，pooled 仅作参考

#12 原实现把一次 golden 运行的全部 trace（5 个 case × 4 次 = 20 条）混在一起算 pooled 变异系数
（`std/mean` of `tool_calls`），单阈值 `COST_CV_MAX` 裁决。

实测（todo-add 第三次评估 run3）：case 之间的难度差直接进了"抖动"——组间均值极差 8.5 步
（c4 6.5 步 vs c1 15.0 步），pooled cv **0.65** > 0.5 → 判"不稳定"；按组内算，逐 case cv 中位数
**0.45** ≤ 0.5 → 稳定。同一批数据得出相反结论，取决于 case 组成而非运行是否稳定。

决定：

1. `runs.json` 条目可带 `case` 字段（谁产 runs.json 谁写；契约见 reference.md）。
2. `score.py` 在**全部**条目都带非空 case 时产出 `cost_by_case`（逐 case 的 mean/std/n/min/max）；
   任一条缺 case / 类型不对 → 整块不产出。半截分组会把两个 case 混成一组，比不分组更危险。
3. `report.py` 的 #12 以**逐 case 变异系数中位数**裁决（阈值 `COST_CV_MAX` 不变，
   作用对象从"20 次混合运行"变为"逐 case 的中位数"，更抗离群点）；`cv_median`、`cv_max`、
   `cv_by_case`、`cv_pooled` 一并写进 `data`，旧口径的分歧点不丢信息。
4. 无 `cost_by_case`（旧产物、旧 harness）时回退 pooled 口径，note 显式标注 `pooled 口径`；
   历史结果目录不重算。

## Consequences

- 跨版本对比 #12 前先看 `data.cv_scope`：`within-case` 与 `pooled` 不是同一口径，不直接比分数
  （ADR-0004 同理：不同测量手段/口径的分数不横向比）。
- 组内 cv 仍含"主运行 vs 延续状态"的路径差——重复运行是为 #15 幂等设计的延续状态链，
  不是同一条件的重测。要纯抖动证据需另开 reset 链（本期未做）。
- `n=4`/case 下 σ 估计仍粗糙（单个离群点会把该 case 的 cv 抬很高），因此取中位数而非最大值裁决；
  最大值与所属 case 在 note/data 中可见，用于定位离群 case。
