# 前端上传、人工复核与出站网络扫描

外部人员不该为了评估一个 skill 去配 Python 路径；扫描也不能只把 POST 当外发——内网 GET、
socket、ssh 同样会把数据带出去。评估失败时用户需要一个可审计的“降级”动作，而不是改 JSON。

决定：

1. `web/app.py` 增加 zip 上传：base64 → 安全解压（拒绝 `..`/绝对路径/符号链接；限制压缩包
   70MB、解压 200MB、文件数 3000）→ 返回 skill 路径；本地路径仍保留。
2. 前端增加 LLM provider 表单（协议 / 端点 / 模型 / key）。优先级：**页面 > config.yaml >
   环境变量 > 官方端点**；key 只用于本次运行，不写 run-meta、不落报告。
3. `static_check.py` 新增 `egress` 组：`curl`/`wget`/`requests.*`/`urllib`/`fetch`/`socket`/
   `ssh`/`scp`/`rsync`/`ftp`/PowerShell 网络 cmdlet 都算；命中仅 warning。`exfil` 仍是强信号
   （带数据/凭据）命中即 fail。这样 GET、内网、非 POST 外发不会被漏掉，也不会把正常 API 调用
   直接判 fail。
4. `report.py` 支持 `overrides.json`：只允许 `fail → warn`，必须带 `reason/reviewer/at`；
   报告 `manual_overrides` + note 标注，前端另写 `manual-overrides.jsonl` 审计日志。
5. `evalset_gen.py` + 前端「评测集」面板：LLM 生成草稿、逐条审核写 `reviews/review.json`；
   生成不写 `meta.json`，冻结仍由条数/质量闸门决定。
6. `parse_frontmatter` 支持 YAML 块标量（`|`/`>`），多行 description 按完整文本计字符；
   `static.json`/报告 #1 增加 `name_chars`，并删除冗余的 `skill_md_body_max_lines`
  （新产物只保留 warn/fail 两档；旧字段仅兼容读取）。
7. 报告 `metrics` 按 #1–#16 排序，新增 `metric_tiers`/`tier_label`；前端按评估深度分组显示，
   不展示内部 ADR 编号，也不把 T2A/T2B 当用户术语。

原因：为什么上传要限制体积与路径——zip slip 和压缩炸弹是本地服务最直接的攻击面；为什么
egress 只 warning——网络调用本身不是缺陷，缺的是“是否传了敏感数据”的证据；为什么人工调整
只允许 fail→warn——升级裁决会让报告失去客观性；为什么生成草稿不自动冻结——LLM 生成的触发集
必须经过条数与质量闸门。

## Consequences

- `web/runs/`、`uploads/real-input/` 都是本地态，进 `.gitignore`。
- 人工调整会改变结论，但报告保留 `manual_overrides` 与审计日志，可追溯。
- `egress` 会增加 warning 数量；它是待人工复核信号，不改变 #4 的 fail 分级。
