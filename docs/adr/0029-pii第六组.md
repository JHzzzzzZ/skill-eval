# #13 增第六组 PII：静态只认格式化的，公司特化信息走 LLM 语义面

#13 的五组覆盖"skill 会做坏事"，没覆盖"skill 带着别人的私人数据跑"：实测带真实员工工号、客户名、内部系统地址的 skill 五组一条不中，而这些
东西随 skill 被复制到用户机器上就是泄漏——工号与客户名没有可枚举的格式，纯正则结构上认不出。

决定：

1. `#13` 扩为**六组**，分组表与命中级别见 `reference.md § 权限边界`；本条取代 ADR-0013 的五组表，
   四组 error、混淆 warning 的分级原则不变。
2. 第六组 `pii` 只认可格式化的个人标识：邮箱、中国大陆手机号、18 位身份证（含校验位）、银行卡（16–19 位 + Luhn）、公网 IPv4；命中**仅 warning**，与 `obfuscation` 同档。
3. 两道过滤：行级占位符（与 `secrets` 组同口径）+ 示例值白名单（示例域名、保留号段、
   GB 11643 标准示例证件号、常见测试卡号）。
4. 语义面新增 `judges/pii.md` 四项检查点（无真实个人标识、无公司内部标识、示例全为占位、
   无未脱敏日志样本）；工号这类只能靠它。
5. `#13` 裁决 = 静态面（五组 + 可移植性闸门）与 pii 评审取**较差者**（ADR-0017）；pii 四项全挂 → fail。

原因：为什么不单开第 20 条指标——ADR-0004 固定 19 条，"包里有没有别人的个人信息"与"权限最小化"同属一个命题。为什么静态面只判 warning——
占位符过滤挡不住自造示例（真实号段格式的假号码），Luhn 挡不住测试卡号，一票 fail 会误杀合法示例；而 PII 命中本身的性质就是"需人工确认这是示例还是真数据"。

## Considered Options

- 并进 `secrets` 组：凭据是"能冒充你"、个人信息是"能定位到人"，处置不同（轮换 vs 脱敏）。
- 只用 LLM 评审：与 ADR-0017 冲突——"有没有邮箱/身份证格式"是可数的静态事实。

## Consequences

- `judges/pii.md` 与 `judges/pii.json` 进评估器指纹（ADR-0010）。
- 六组正则表在扫描器源码里，自命中风险仍在（拼接书写 + `static-check:ignore`，自检守住）。
- 静态面有噪声（公网 IP、真实号段格式的示例号码），定位是提示人工复核而非定罪。
