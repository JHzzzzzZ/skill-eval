# #13 增第六组 PII：静态只认格式化的，公司特化信息走 LLM 语义面

#13 的五组（危险命令 / 凭据 / 注入 / 外发 / 混淆）覆盖的是"skill 会做坏事"，没覆盖"skill 带着别人的私人数据跑"。
实测缺口来自自评：包里带真实员工工号、客户名、内部系统地址、未脱敏导出文件的 skill，五组一条都不命中——
这类内容随 skill 被复制到用户机器上就是泄漏，而流水线看不见。工号、内部代号、客户名没有任何可枚举的格式，
纯正则结构上认不出。

决定：#13 扩为**六组**（分组表以本 ADR 为准，取代 ADR-0013 的五组表；0013 的命中分级原则不变）。

| 组 | 内容 | 命中级别 |
|---|---|---|
| `dangerous` | 危险命令（rm -rf / sudo / curl\|sh …） | error → fail |
| `secrets` | 私钥 PEM、云厂商/GitHub/Slack 前缀、JWT、高熵赋值（占位符过滤） | error → fail |
| `injection` | 指令覆盖短语（中英）、"不要告诉用户"、伪 system 段、零宽/双向控制字符 | error → fail |
| `exfil` | curl -d/-X POST、requests.post、nc -e、读 `.ssh`/`.aws/credentials`/`.env` | error → fail |
| `obfuscation` | base64 解码、eval/exec、连续 `\xNN`、长 base64 blob | warning（人工复核） |
| `pii` | 邮箱、中国大陆手机号、18 位身份证、银行卡（16–19 位 + Luhn）、公网 IPv4 | warning（人工复核） |

1. `pii` 静态面只认**可格式化**的个人标识，并带两道过滤：复用 `PLACEHOLDER_RE`（占位符行不计），
   加示例值白名单（`example.com`、`13800138000`、`11010119900307xxxx` 这类明显示例）。
2. 语义面新增 `judges/pii.md`，四项检查点：无真实个人标识、无公司内部标识（工号/内部系统地址/客户名/
   未公开代号）、示例数据全为占位、无未脱敏的日志/样本/导出文件。工号这类只能靠它。
3. #13 裁决 = 静态面（五组 + 可移植性闸门）与 pii 评审的**较差者**（ADR-0017 多源口径：
   静态主源 + LLM 辅证）。pii 评审 `score=0`（四项全挂）→ #13 fail。

原因：为什么不给 PII 单开第 20 条指标——ADR-0004 固定 19 条、报告 key 恒定，"包里有没有别人的个人信息"
与"权限最小化"是同一命题（能拿到不该拿的数据）。为什么静态面只判 warning——占位符过滤挡不住自造示例
（`13812345678` 是真实号段格式），Luhn 也挡不住测试卡号，一票 fail 会误杀文档里合法的示例；
而 PII 命中本身的性质就是"需人工确认这是示例还是真数据"。

## Considered Options

- 把 PII 并进 `secrets` 组：凭据是"能冒充你"，个人信息是"能定位到人"，处置方式不同（rotation vs 脱敏），
  混一组会让命中摘要读不出该做什么。
- 只用 LLM 评审、不做静态：与 ADR-0017 的同一原则冲突——"有没有邮箱/身份证格式"是可数的静态事实。

## Consequences

- 新增 `judges/pii.md` 与 `judges/pii.json` 产物，两者都进评估器指纹（ADR-0010）。
- 六组正则表都在扫描器源码里，自命中风险仍在：模式表按惯例拼接书写 + `static-check:ignore`，
  评估器自检（`test_evaluator_self_check_passes`）继续守这条线。
- PII 静态面有噪声（公网 IP、真实号段格式的示例号码），定位是"提示人工复核"而非"定罪"。
