# 评测集：人工上传优先，自动生成兜底且必须人工审核，冻结于评估器目录

评测集质量决定精准触发（#1）与结果可验证（#9）的可信度。决定：

1. 人工上传的评测集优先采用
2. 无评测集时由 LLM 自动生成，但**必须经人工审核确认后才冻结**
3. 冻结位置在**评估器目录** `skill-evaluator/evalsets/<skill-name>/v<N>/`，不放被测 skill 目录
4. 评测集一旦冻结不再重新生成；版本演进永远复用同一份，只换被测 skill 版本

原因：纯自动生成的"应触发" prompt 往往和 description 措辞过于相似，测不出真实 recall。"应触发"的 5-10 条用户实际措辞应由上传者提供，缺时自动生成待审核。评测集放评估器目录是为了保持被测 skill 的 worktree 干净（被测对象本身也是评估输入，不能被评估产物污染）。

## Consequences

- 每个新 skill 首次评估前有一次人工审核环节，无法全自动
- 评测集按 skill 名聚合，跨版本共享

---

**修订（ADR-0010）**：第 2 条「必须人工审核后冻结」已改为 LLM 自动审核即冻结（`reviewed_by: "ai"`），审核模型必须与生成阶段不同源；人工复核后可升级覆写为 `"human"`。其余条款（人工上传优先、冻结位置、冻结后复用）不变。
