# MVP 分三期：先确定性测量，后 LLM 评审，最后高阶分析

19 条指标不一次做完。决定分三期：

1. **第一期（MVP）**：静态检查（#2/#7/#13）+ 触发评测（#1）+ 主运行/基线 A/B（#4/#5/#8/#9）+ report 产出 + 评测集冻结流程
2. **第二期**：LLM 评审组（#3/#6/#11/#16/#17/#18/#19）+ 重复运行（#12/#15）
3. **第三期**：trace 对照的过程验证（#10）、消融运行（#6 实证）、版本演进面板（#14）

原因：第一期全是确定性或高可靠测量，能覆盖一半指标且结果可信；LLM 评审类可靠性次之；trace 分析与消融是锦上添花。先跑通端到端流程再逐步加指标，避免一次性设计过重。

## Consequences

- 第一期报告中 #3/#6/#10/#11/#12/#15/#16/#17/#18/#19 全部标 `skipped`，用户可见完整指标清单和当前覆盖范围
- N（重复运行次数）等参数写成 reference.md 中的可配项，不是硬编码
