# 指标集收缩到 16 条并按档位重编号

T4 暂不开放，#19 副作用可逆撤掉；报告里 T4 专属的 #10 过程可验证、#14 版本演进没有测量载体，
保留编号会留下永远 skipped 的空槽。用户要求编号连续、相邻编号尽量落在同一档。

决定：

1. 指标 19 → 16：删 #19、#10、#14。#6 低冗余保留——它有 T1 评审面，T4 消融面休眠。
2. 编号按“先档位 T0→T3、再旧编号”重排：
   T0 #1–#4（旧 #2/#3/#7/#13）；T1 #5–#9（旧 #6/#11/#16/#17/#18）；T2A #10（旧 #1）；
   T2B #11–#12（旧 #5/#8）；T3 #13–#16（旧 #4/#9/#12/#15）。旧 #3 跨 T0/T1
   （行数主源 + 语义辅证），仍占一个号。
3. `report.json` 顶层加 `schema: 2` 与 `legacy_id_map`；`evolution.py` 只比同 schema，
   旧报告不重写、不迁移。
4. T4 专属脚本与 rubric（`process.py` / `evolution.py` / `ablation.py` / `judges/side-effects.md`）
   移入 `attic/`（脚本、rubric 与对应测试），不进包、不进 `check-deps.sh`、不跑测试；将来 T4 回归就追加 #17/#18，
   不重排 1–16。

原因：为什么不留空号——空槽会让“指标总览”和 `conclusion()` 永远带 skipped，读者分不清
“没测”与“撤掉”；为什么不给每条加 `legacy_id`——映射表一处就够，逐条字段会让报告变胖，
还要同步 16 个测试；为什么不重写旧报告——旧报告是历史证据，重写等于伪造当时的评估器口径。
代价：旧 ADR 里的 `#N` 引用、9 份 judges 映射、报告总览全部要跟着改，只能靠 `legacy_id_map`
和新 ADR 追溯。

## Considered Options

- 保留旧编号、只隐藏 #10/#14/#19：不满足“编号连续”，且新读者会问 #10 去哪了。
- 每条指标带 `legacy_id`：工具友好，但报告契约多一层，收益不抵维护成本。

## Consequences

- `report.py` 的 `ALL_KEYS`、`DIM_NAMES`、advice 反链、报告总览全部改；
  `tests/test_report*.py` 的 19-key 断言重写。
- 旧报告与新报告不可横向比；`evolution.py` 必须先看 schema。
- `attic/` 内容不随包分发，避免死代码被当成可用功能。
