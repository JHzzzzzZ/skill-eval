# 指标归约为三种测量手段，五类运行场景；报告不合成总分

19 条指标若各自独立验证需要 19 次运行，成本不可接受。决定：

1. **按测量手段归约**：静态检查（脚本，#2/#7/#13）、LLM 评审（temperature 0、单次、结构化 JSON，#3/#6/#11/#16/#17/#18/#19）、沙箱运行（#1/#4/#5/#8/#9/#10/#12/#15）
2. **按运行场景合并**：触发评测、主运行（Golden Run）、基线 A/B、重复运行（N=3）、消融运行，共 5 类；一次运行同时服务多个指标
3. **报告 19 条独立打分，不合成加权总分**；未运行的指标标 `skipped` 而非 0 分

原因：许多指标是"质"的判断（如 fallback 设计好坏），加权合成制造虚假精确；LLM 评审分数有抖动，用户已确认暂不做多次取中位数（后续可切换为 3 次取中位数或多模型交叉）。

## Consequences

- 第二期做 LLM 评审组与重复运行，第三期做 trace 过程验证、消融运行、版本演进面板（MVP 切分见 ADR-0005）
- 报告结论只按"必测全过 / 有警告 / 有失败"三档呈现，不做总分
