# 指标可多源：确定性面为主源，LLM 面为辅证

#3 正文精简的三个检查点里，只有"行数克制"是可数事实，却和两条语义判断一起交给 LLM 判
（阈值由本仓 rubric 自己在 `02d15de` 把软线 ">150 行倾向臃肿" 硬化成 "不超过 150 行"）。
LLM 判可数项会算错、不可复现，阈值也不在代码里、无测试。同时 `CONTEXT.md` 的"每条指标归属
恰好一种测量手段"与代码早已不符：#8、#6、#17/#18 都是多源，词条是旧的。

决定：

1. 指标允许**一个主源 + N 个辅证**；裁决"主源优先"，辅证以原始形状保留在 `data` 里不丢，不做加权合成——同 ADR-0004 不合成总分。
2. #3 行数改由 `static_check.py` 测：`skill_md_body_lines`（口径 = `parse_frontmatter` 之后全文，含空行与代码块）+ 自描述阈值 `skill_md_body_max_lines`；超线即 **warn**，不 fail（与 #2 description token 超限同级）。两条语义检查点仍由 `judges/brevity.md` 判，行数一项从 rubric 删除——同一事实只留一个判官。
3. `SKILL_MD_BODY_MAX_LINES = 150` 定性为**自定启发式 + 可配常量**，不是需求原文数字（`prompt.txt` 已不入库，无法追溯）；阈值随产物自描述，`report.py` 不复制常量，旧 `static.json` 无该字段则闸门关闭。
4. 语义面未跑时 #3 仍标 `skipped`（行数证据照样进 `data`），不冒充 pass。

原因：可数事实交 LLM 判既不稳也不可追账，而"正文精简"缺了客观尺寸就只剩主观判断。
为什么不并入 #2：#2 的产物是 frontmatter 元数据，行数属正文，合并会让 #2 的定义漂移，
且 #3 仍要留两条语义项，静态面只是换了个挂载点。为什么不是整体删掉：行数是大文件臃肿的
唯一客观证据，留着可复现。

## Considered Options

- 静态项塞进 `items` 合并计分：`judge_runner.py` 要求每项带原文引用 `quote`，静态项没有可引原文；且 `judges/<metric>.json` 的定义是"LLM 评审输出"，混入非 LLM 内容会毁掉该定义。
- 保留 LLM 判行数、静态面只当证据展示：判决仍不可复现，等于没改。

## Consequences

- 改 `judges/*.md` 即改评估器指纹（ADR-0010）：本次改动之前的报告全部 `comparable=false`。
- #3 的 `data` 同时含静态面与评审面字段；渲染层按"有 `items` 即按评审面渲染"，行数进折叠的原始 JSON。
- 行数由常量说了算，LLM 那种"152 行但都必要就放过"的体谅消失——所以阈值必须可配。
